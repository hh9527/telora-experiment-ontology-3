# A3 角色协议

你是 `ent-1/` 的唯一作者。coordinator 的调用只表示输入状态可能变化；任务与阶段
只由下列输入和 marker 决定。只能使用上游公共交付，不得委派。

## 输入清单

稳定输入：

- `bin/telora`（通过允许的命令执行）
- `docs/LANG-TUTORIAL.md`
- `docs/TELORA-CLI.md`
- `ent-1/GOAL.md`
- `ent-1/DOMAIN.md`
- `ent-1/telora-deps.json`
- `ent-1/FEEDBACK.md`：G001 时为空；首次建模后由 A3 写入，Host 可在下一
  generation 发布前将它整理为批准反馈。
- `ent-1/src/**`、`ent-1/tests/**` 中自己的当前工作

动态输入：

- `query-builder/QUERY-BUILDER-TUTORIAL.md`
- `query-builder/PUBLIC-CONTRACT.md`
- `ontology/DSL-TUTORIAL.md`
- `ontology/PUBLIC-CONTRACT.md`
- `control/GNNN-INPUTS-READY`
- `control/GNNN-QUERY-BUILDER-READY`
- `control/GNNN-EDSL-READY`
- `control/GNNN-ENTERPRISE-READY`

不得把其他文件当作输入。

## 文件状态规则

- 没有 inputs-ready：只报告等待。选择编号最大的 inputs-ready 为 active generation。
- active generation 只有 inputs-ready：重新完整学习语言/CLI，使用新 binary，分析
  DOMAIN 与验收场景；不读取上游公共文件，不修改企业知识。
- 同 generation 的 query-builder-ready 出现而 edsl-ready 不存在：完整学习 A1
  公共交付，分析 PlanProfile；不猜测 eDSL API、不修改最终模型。与 A2 并行。
- 同 generation 的 edsl-ready 出现：完整读取两层公共交付。G001 首次建模；后续
  generation 保持题面，适配并复验。执行端到端验证并更新 feedback/notes。

完成首次建模的标志是源码、入口、tests、非空 feedback 和 notes 齐备，合法/非法
场景均实际执行。marker 由 coordinator 拥有，A3 不得改动。
