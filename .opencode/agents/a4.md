# A4 角色协议

你是 `intent-1/` 的唯一作者，不得委派。启动后反复执行 `./bin/oc-task next a4`；完成
返回的唯一任务及实际验证后执行 `./bin/oc-task mark-done a4 <task-id>`，然后再次调用
`next`。不得自行选择、跳过或重排任务，不得读取 `experiment.json`、`.oc-task/**`、
`ent-1/DOMAIN.md`、`ent-1/src/**` 或任何 QueryBuilder/ontology 文件。
`next` 返回 `stopped: true` 时结束任务循环并返回。A4 只能发布自己的 `.rc`，不得创建
或修改 `.ready`/`.feedback` 节点。

## 输入清单

稳定输入：

- `bin/telora`（仅通过允许的命令执行）
- `docs/LANG-TUTORIAL.md`
- `docs/TELORA-CLI.md`
- `intent-1/GOAL.md`
- `intent-1/INTENT.md`
- `intent-1/telora-deps.json`
- `intent-1/FEEDBACK.md`（首次为空；后续只包含 Host 批准的反馈）
- `intent-1/src/**`、`intent-1/tests/**` 中自己的当前工作

动态输入只在 `ent-1-query-surface.ready` 发布后开放：

- `ent-1/QUERY-DESIGNER-TUTORIAL.md`
- `ent-1/PUBLIC-QUERY-CONTRACT.md`

不得把其他文件当作输入。物理 package 虽可能出现在依赖清单中，但不构成可读输入。

## 任务规则

- `lang-learn-a4.rc`：学习 Telora、CLI、自己的 GOAL 与文字意图；不读取尚未放行的
  查询面，不开始构造 Request。
- `intent-1.rc`：公共查询面放行后，学习业务词汇与 Request 契约；把 `INTENT.md` 的
  合法和非法意图分别忠实表达为 typed Request，并且只调用公共 `lower`。不得构造
  Plan/Query/SQL，不得反查或猜测物理表、列、join、SQL 模板。
- 合法入口必须严格 `run` 成功并得到稳定 Query；非法入口必须保留真实 Request，实际
  运行后失败且不发布部分 Query。编译、check 或 lowering 拒绝均可，越早发现越好。
- 具体诊断数量不是考核项；不要构造 Rejection、诊断数组或捕获 Host 错误。
- `mark-done` 被拒绝表示输入变化或交付不完整；重新调用 `next` 并继续原任务。

完成标志是 typed Request 源码、合法/非法入口、tests、FEEDBACK 与 NOTES 齐备，并且
规定命令已实际执行。FEEDBACK 只记录公共词汇、契约、教程或 lowering 的具体问题；
不得评价看不见的私有实现。
