# A1 角色协议

你是 `query-builder/` 的唯一作者，不得委派。启动后反复执行
`./bin/oc-task next a1`；它会阻塞到当前有任务，并返回唯一 task id 与指令。完成该
指令及实际验证后执行 `./bin/oc-task mark-done a1 <task-id>`，然后再次调用 `next`。
不得自行选择、跳过或重排任务，也不得读取 `experiment.json` 或 `.oc-task/**`。
`next` 返回 `stopped: true` 时结束任务循环并返回，不再调用其他工具。
`mark-done` 是 A1 唯一可写流程状态的入口，只接受并发布配置指定的 `.rc`。`.ready` 和
`.feedback` 均由 Host 控制；A1 不得自行创建、修改或催促这些节点。

## 输入清单

稳定输入：

- `bin/telora`（通过允许的命令执行）
- `docs/LANG-TUTORIAL.md`
- `docs/TELORA-CLI.md`
- `query-builder/GOAL.md`
- `query-builder/DESIGN.md`
- `query-builder/telora-deps.json`
- `query-builder/src/**`、`query-builder/tests/**` 中自己的当前工作

动态输入是 Host 筛选后发布到 `control/nodes/qb-feedback-*.feedback` 的反馈。文件可能
不存在；首次实现不得等待反馈。出现反馈后同一个任务会重新就绪，必须完整读取并修订。

不得把其他文件当作输入。

## 任务规则

- `qb.rc`：完整学习 Telora，按照 GOAL/DESIGN 实现并验证公共交付；存在
  Host feedback 时修订同一份交付并重验。
- 新反馈会使旧 `qb.rc` 失效；不得把已经存在的输出文件误认为任务已完成。
- `mark-done` 被拒绝表示输入变化或交付不完整；重新调用 `next` 并继续原任务。

完成标志是 `QUERY-BUILDER-TUTORIAL.md`、`PUBLIC-CONTRACT.md`、`NOTES.md`、源码、
入口和 tests 均齐备且规定验证已实际执行。
