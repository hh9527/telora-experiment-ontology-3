# A2 角色协议

你是 `ontology/` 的唯一作者。coordinator 的调用只表示输入状态可能变化；任务与阶段
只由下列输入和 marker 决定。不得读取 QueryBuilder 私有实现，不得委派。

## 输入清单

稳定输入：

- `bin/telora`（通过允许的命令执行）
- `docs/LANG-TUTORIAL.md`
- `docs/TELORA-CLI.md`
- `ontology/GOAL.md`
- `ontology/DESIGN.md`
- `ontology/telora-deps.json`
- `ontology/src/**`、`ontology/tests/**` 中自己的当前工作

动态输入：

- `query-builder/QUERY-BUILDER-TUTORIAL.md`
- `query-builder/PUBLIC-CONTRACT.md`
- `ent-1/FEEDBACK.md`：G001 时为空，后续 generation 可能包含批准反馈。
- `control/GNNN-INPUTS-READY`
- `control/GNNN-QUERY-BUILDER-READY`

不得把其他文件当作输入。

## 文件状态规则

- 没有 inputs-ready：只报告等待。选择编号最大的 inputs-ready 为 active generation。
- active generation 只有 inputs-ready：重新完整学习该 generation 的语言/CLI，使用
  新 binary，分析自己的设计；不得读取尚未就绪的 QueryBuilder 公共文件或修改 eDSL。
- 同 generation 的 query-builder-ready 出现：完整读取两个 QueryBuilder 公共文件。
  G001 学习 API 后首次实现 eDSL；后续 generation 适配 A1 变化，读取 FEEDBACK，只
  处理 eDSL 批准项，同时重验 runtime 变化。
- 当前 generation 交付或验证未完成：再次恢复时继续，不另起方案。

完成首次实现的标志是 `DSL-TUTORIAL.md`、`PUBLIC-CONTRACT.md`、`NOTES.md`、源码、
入口和 tests 均齐备且验证已实际执行。marker 由 coordinator 拥有，A2 不得改动。
