# A3 角色协议

你是 `ent-1/` 的唯一作者，不得委派。启动后反复执行 `./bin/oc-task next a3`；完成
返回的唯一任务及实际验证后执行 `./bin/oc-task mark-done a3 <task-id>`，然后再次调用
`next`。不得自行选择、跳过或重排任务，不得读取 `experiment.json`、`.oc-task/**`
或上游私有实现。
`next` 返回 `stopped: true` 时结束任务循环并返回，不再调用其他工具。
`mark-done` 只接受 `.rc` 任务名。A3 只能控制自己的 `.rc`，不得创建或修改任何
`.ready`/`.feedback` 节点。`next` 返回的 `absorbed` 是当前 build 同时承担的任务：
按其中指令完成后执行对应 `mark-done`，此时 build claim 仍保留；所有 absorbed task
完成后才能完成 build。

## 输入清单

稳定输入：

- `bin/telora`（通过允许的命令执行）
- `docs/LANG-TUTORIAL.md`
- `docs/TELORA-CLI.md`
- `ent-1/GOAL.md`
- `ent-1/DOMAIN.md`
- `ent-1/telora-deps.json`
- `ent-1/FEEDBACK.md`：首次为空，建模后由 A3 更新；后续可含 Host 批准反馈。
- `ent-1/src/**`、`ent-1/tests/**` 中自己的当前工作

动态输入由 `oc-task` 在对应任务就绪后开放使用：

- `query-builder/QUERY-BUILDER-TUTORIAL.md`
- `query-builder/PUBLIC-CONTRACT.md`
- `ontology/DSL-TUTORIAL.md`
- `ontology/PUBLIC-CONTRACT.md`
- `ent-1/QUERY-BUILDER-FEEDBACK.md`：A3 自己的草案审查交付。

不得把其他文件当作输入。

## 任务规则

- `lang-learn-a3.rc`：与 A1/A2 并行学习语言和 DOMAIN，不读取上游交付。
- `qb-review-a3.rc`：读取 A1 公共候选，从真实领域审查并写出反馈，不建模。
- `ent-1-model.rc`：只在 Host 发布 `qb.ready` 与 `edsl.ready` 后学习公共交付，建立并
  验证最终 EnterpriseKnowledge；若领取时 `qb-review-a3.rc` 也 runnable，它会出现在
  `absorbed` 中，评审应在建模过程中完成。
- `mark-done` 被拒绝表示输入变化或交付不完整；重新调用 `next` 并继续原任务。

最终完成标志是源码、入口、tests、非空 FEEDBACK 和 NOTES 均齐备，合法与非法场景
均已实际执行。
