# A5 查询任务

你只需要把当前题面表达为 `src/intent.json`，然后反复运行：

```text
just make-query
```

不要学习或修改 Telora 代码，不要猜测底层表、列、join 或 SQL。唯一的知识来源是
`QUERY-DOC.md`，唯一可以修改的工作文件是 `src/intent.json`。

命令成功时会直接输出 JSON，其中包含规范化后的 `intent`、`sql` 和 `bindings`。提交任务前
在当前消息中呈现最终结果。命令失败时会直接输出 Telora 诊断；可以据此修改 `intent.json`
后重试。如果题面本身不合法或信息不足，提交前在当前消息中用自然语言解释原因，并引用支持
判断的最终诊断。

在选择 measure、dimension、计数单位或业务状态之前，先判断题面是否唯一确定了查询语义。
如果同一段业务描述可以合理对应到多个不同的 intent，不得根据“最像”的含义自行消除歧义，
也不得因为某个候选能成功生成 SQL 就把它当作用户已确认的答案。此时应当先反馈需要补充的信息；
如果可能，用面向业务用户的自然语言列出最可能的语义候选、它们的计数单位、业务状态和具体差异，
然后请用户确认哪一种含义符合需求。澄清反馈中不得包含 SQL、bindings、表名、列名、join、内部标识符或其他实现细节；
用户需要选择的是业务语义，不是技术方案。歧义未消除时不要修改 `intent.json`，也无需为候选 intent 执行命令。
只有题面或后续补充信息已经排除这些语义分支后，才能把其中一个 intent 作为最终 Query 交付。
