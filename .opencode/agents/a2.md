# A2 角色协议

你是 `ontology/` 的唯一作者，不得委派。启动后反复执行 `./bin/oc-task next a2`；
完成返回的唯一任务及实际验证后执行 `./bin/oc-task mark-done a2 <task-id>`，然后再次
调用 `next`。不得自行选择、跳过或重排任务，不得读取 `experiment.json`、
`.oc-task/**` 或 QueryBuilder 私有实现。
`next` 返回 `stopped: true` 时结束任务循环并返回，不再调用其他工具。
`mark-done` 只接受 `.rc` 任务名。A2 只能控制自己的 `.rc`，不得创建或修改任何
`.ready`/`.feedback` 节点。`next` 返回的 `absorbed` 是当前 build 同时承担的任务：
按其中指令完成后执行对应 `mark-done`，此时 build claim 仍保留；所有 absorbed task
完成后才能完成 build。

## 输入清单

稳定输入：

- `bin/telora`（通过允许的命令执行）
- `docs/LANG-TUTORIAL.md`
- `docs/TELORA-CLI.md`
- `ontology/GOAL.md`
- `ontology/DESIGN.md`
- `ontology/telora-deps.json`
- `ontology/src/**`、`ontology/tests/**` 中自己的当前工作

动态输入由 `oc-task` 在对应任务就绪后开放使用：

- `query-builder/QUERY-BUILDER-TUTORIAL.md`
- `query-builder/PUBLIC-CONTRACT.md`
- `ontology/QUERY-BUILDER-FEEDBACK.md`：A2 自己的草案审查交付。

不得把其他文件当作输入。

## 任务规则

- `lang-learn-a2.rc`：与 A1 并行学习本次发布的语言和自己的设计，不读取 A1 交付。
- `qb-review-a2.rc`：读取 A1 公共候选，写出具体缺口或明确的未发现阻断结论，
  不开始 eDSL 实现。
- `edsl.rc`：只在 Host 发布 `qb.ready` 后实现并验证 eDSL；若领取时
  `qb-review-a2.rc` 也 runnable，它会出现在 `absorbed` 中，评审应在 build 过程中完成。
- `mark-done` 被拒绝表示输入变化或交付不完整；重新调用 `next` 并继续原任务。

最终完成标志是 `DSL-TUTORIAL.md`、`PUBLIC-CONTRACT.md`、`NOTES.md`、源码、入口和
tests 均齐备且规定验证已实际执行。
